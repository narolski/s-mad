### Findings (most severe first)

**1. Blocker: Part A's split shares persons and images between the probe's fit rows and its read rows, and the leak pushes toward "low ceiling".**
- I checked this against `AR1/pool.csv`, which gives each host's two-person partner (`B_pid`).
- 99 of the 100 development hosts are partners of test hosts. 99 of the 191 test hosts have a development host as partner. 51 development hosts have a test host as partner.
- The partner photo B is the partner's own S photo on 291 of 291 hosts.
- S3 blends H with S, and S4 blends H with B (`AR1/prereg.md:182`). So the same S image sits in a label-0 fit row (the development host's S3) and in a label-1 read row (a test host's S4), and the reverse holds for the 51.
- A probe that memorises that image is pushed toward the wrong answer on the read. This biases the result toward "low ceiling".
- Only 80 test hosts are clean (partner not a development host, and not a development host's partner).
- **Fix.** Make the binding read the 80 clean test hosts, with H0 on the same rows. Print the 191-host read. Replacement code for `part_a`, after `tst` is built:
```python
pool = {r["pid"]: r["B_pid"] for r in csv.DictReader(open("/mnt/t7/smad_next/AR1/pool.csv"))}
devh = set(dev["host"]); devp = {pool[h] for h in devh}
clean = np.array([pool[h] not in devh and h not in devp for h in tst["host"]])
# binding: auc_core_clean_{k} = N.auc(s[core & y4 & clean], s[core & ~y4 & clean]); bootstrap over clean hosts
```

**2. Major: "low ceiling" cannot tell missing information from too little data.**
- At 80-191 read hosts the AUC standard error is about 0.03-0.04. The probe-minus-H0 difference has an SE of roughly 0.02-0.03. A point value ≤ H0 + 0.03 therefore passes even when the true gain is +0.05.
- The result is also partly known in advance. The review found that H1d, a linear head fitted on L development hosts with S3 = 0 and S4 = 1 among its rows, has an S4-vs-S3 AUC within 0.011 of H0 on 5/5 seeds (result.md:80). The prereg must say so.
- **Fixes in code, no GPU:**
  - a learning curve: the linear probe on 25/50/75/100 fit hosts, read on the clean hosts;
  - a host-level label-permutation null: swap S3/S4 labels within each host, 20 draws, printed;
  - `lin_T` and a probe fitted on core rows only, both printed.
- **Replacement row 1:** "low ceiling: on ≥ 4 seeds the upper 95% bound of (linear − H0) ≤ +0.05 AND MLP ≤ H0 + 0.05 AND the 100-host AUC ≤ 50-host AUC + 0.02 (plateau) AND lin_T ≤ H0 + 0.05. Reading: a linear or small-MLP head fitted on these development hosts does not separate S4 from S3 better than the frozen head; this is evidence, not proof, that the features lack the distinction." Delete "no head-level method can supply it".
- On the variants: S3_bg and S4_bg differ only in warp geometry (R2w against R2w4). Blanking is balanced across labels, so it is not a label shortcut. It does dilute the fit, which is why the core-only probe should be printed.

**3. Major: the isotropic null cannot fail, so it is not a check.**
- A random rank-7 subspace in 512 dimensions removes about 7/512 of any direction. The review's rank-1 isotropic null removed at most 0.00-0.10. It will never come within 0.3 of 1, so the "null" condition always holds.
- Separately, E7 and LEACE zero the half-A per-mask mean differences by construction. Two-sided logits and the per-mask condition then follow almost automatically by transfer, so the real tests are flags, ranks and cost.
- **Fixes:**
  - (a) Add a half-B ceiling eraser E7c, fitted on the read rows like H3c. If E7c is not clean on ≥ 4 seeds, read "criteria unreachable (inconclusive by design)". Check this row first, after the floor.
  - (b) Keep the isotropic nulls, but use them as the cost reference: "no cost: loss ≤ max(0.02, the largest loss among the 20 isotropic nulls)". The p99 cut rests on about 13 tail rows of P (1,290 rows), so any rank-7 erasure moves recall.
  - (c) Print a head-matched null: random rank-7 subspaces whose projection of w matches E7's.

**4. Major: landmark_combined (C) should not be a binding detection cost.**
- Shortcut cues alone separate C at 0.964 (FLOORS.md:21, 32), so a C recall loss can be a shortcut being removed.
- C is also cross-domain for refitted heads (label at line 263).
- **Replacement:** "no cost: recall loss on L test-host R4 at the head's own p99 cut ≤ the threshold in finding 3, AND the R4-vs-R0 AUC loss on L test hosts ≤ 0.01; C recall and C AUC printed."
- R4 has 382 rows, so its recall SE is about 0.02. That is a second reason for the null-based tolerance.

**6. Minor: LEACE is fragile at about 1,660 fit rows in 512 dimensions.**
