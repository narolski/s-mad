## 2. Findings

1. **Major. The reproduction gate will probably return "not determined" for most methods, and it selects seeds on test scores.**
   - Rule: a retrain counts only if it is within max(1.5, 25%) of the published EER on every gate cell (`prereg.md:121-129`, `ad5_analyse.py:157-162`); with fewer than 4 such retrains the verdict is "not determined" (`:111-116`). MADation has 11 gate cells, many with a 1.5-point window.
   - Evidence the window is too tight: one genuine photo is 0.49 points and the same release moves up to 1.5 points between machines (`ideas/CONSOLIDATED_v3.md:64-66`). The authors' own log of the released ViT-L/14 checkpoint prints FRLL AMSL 12.08 (`release_logs/vitl14_madation/training.log:426`) against 7.26 published (window 1.8). The same log equals Table 1 exactly on MAD22 and MorDIFF (`:411-416`), so Table 3 comes from another run or other frames.
   - Bias: retrains that land near the release's EER on a cell are more likely to share its effects on that cell, which pushes the verdict toward "property of the method".
   - Fix (amendment, no GPU): make the all-five-seeds line the headline; keep the gate as a per-seed label; apply it per cell, as the own-crop re-score (RS1) does per row; add a second window around the release's EER through our path; register the sentence used when fewer than 4 reproduce ("k of 5 retrains with the authors' code reproduce the published numbers").

2. **Major. MixFaceNet-MAD and SelfMAD keep one checkpoint, so the authors' rule can never be printed beside ours, and a time-limit kill loses the whole run.**
   - Evidence: `src/AD5/mixfacenet_ad5.patch:8-16` has a single `torch.save` after epoch 100, while the authors keep the best epoch with patience 20 (`build/smdd_src/main.py:163-171`). `build/selfmad_src/train__.py:193-199` saves only the last epoch, while the shipped default is `testset_best` (`configs/train_config.json:6`).
   - Why it matters: 100 epochs without early stopping may be far from the release, and a miss would be unexplainable.
   - Fix: save the state dict every epoch for MixFaceNet-MAD (11 MB each) and every 5 epochs for SelfMAD (model only, about 85 MB each). `torch.save` draws no random numbers, so training is unchanged. Epoch 100 stays the registered reading; other epochs are descriptive. Resubmit MixFaceNet-MAD with `--time=12:00:00`.

3. **Major. Queued tasks read code from a shared path that can change under them.**
   - Evidence: every task sources `packs/AD5/code/src/AD5/athena/ad5_common.sh` and runs `code/build/*` at start (`ad5_madation_train.sbatch:23,42-45`); `build_packs.sh:11` does `rm -rf code`.
   - The local pack copy is already not what was submitted: `/mnt/t7/smad_next/AD5/packs/code/CODE_SHA256SUMS` lists `ad5_madation_train.sbatch` as f01902c2…, the repository file is 39d4e7dc…; `ad5_common.sh` and the MixFaceNet job file differ too.
   - Fix: put every change (finding 2, SelfMAD) in a new folder `code_v2/`, never touch `code/` while tasks are pending, and record the Athena tree's hash list in the README.

4. **Major. The scoring job is out of date against the own-crop re-score (RS1) amendments 2 and 3.**
   - Evidence: `ad5_score_rel.sbatch:61` calls `crop`, where RS1 now calls `cropx` (`src/RS1/athena_rs1.sbatch:75`). It does not unpack `rs1a_pack_raw.tar` (`:36-37`), and it reuses the crops made on the DGX (`:81`).
   - Why it matters: native photos cropped on one machine and history-matched photos on another confound the history effect; RS1 measured box shifts up to 15.9 px.
   - Also: `env/score_requirements.txt` lists no facenet-pytorch, so the crop step looks likely to fail. SelfMAD's gate should use both genuine definitions (RS1 amendment 2c).
   - Fix: adopt RS1's amendments in an AD5 amendment, reuse RS1's crop files by hash, and run the scoring job with `LIMIT=8` while training runs.

5. **Major. For ViT-L/14 (62 of 111 GPU-hours), 6 of 7 primary readings sit on MorDIFF** (`prereg.md:147-149`). The release is predicted "not reproduced" there (RS1 `prereg.md:22`), and the storage-history failure is not shown for this recipe (`CONSOLIDATED_v3.md:44-50`).
   - Fix: name primary cells per method by rule (first reproduced cell of a fixed list) and add the JPEG quality 50 and 0.5-rule readings, where this recipe is reported to fail.
