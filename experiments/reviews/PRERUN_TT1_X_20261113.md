- Evidence:
  - The main job's `finish()` hashes everything in the shared `/workspace/tt1/logs` (`remote_tt1_fs.sh`: `(cd "$B/logs" && sha256sum * > .../logs_fs.sha256)`).
  - `drive_tt1_fs.sh` pull then checks every listed file (`sha256sum -c ../logs_fs.sha256`, around line 47). It never writes TT1_DONE on a mismatch.
  - TT1-X writes into the same folder: `$B/logs/remote_sp.log` (drive_tt1_x.sh:31) and `$B/logs/sp_score.log` (remote_tt1_x.sh:65,74,76).
  - prereg_x_block.md:34 starts X "once the three Sp tars are fetched". That is about 12:45-12:55, while the main job (about 12:45-13:30) is still running.
  - So remote_sp.log exists when the main job hashes the folder, and keeps growing ("lock taken", scoring lines). The main pull then fails for good.
- The same edit fixes a second problem. prereg_x_block.md:35 says that taking the lock makes X run after the main job, but flock is not FIFO. If X is started before the main job is waiting on the lock, X can run first.
- Fix (amendment line, no code change): "drive_tt1_x.sh start is run only after `/mnt/t7/smad_next/vast/pn1fs/tt1/TT1_DONE` exists (main job verified, two copies). Expected X end therefore about 13:55, still before the 14:51 skip point."
