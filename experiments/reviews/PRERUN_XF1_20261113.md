**Pre-run check of the FFHQ FaceMorpher read (XF1), smad-next commit 3abd284**

## 1. Verdict: GO WITH FIXES

Nothing breaks a rule, and the job itself is sound. But the main premise of XF1 is false. FM(H,H) is not a real render: it is the plain photo H with a rounding error. So read 1 is a two-person morph against an untouched photo, and the resampling confound XF1 was built to remove is still there. Fixes F1 to F5 below must go in before you register.

I measured pixels on the 299 host triples (development FFHQ only). Scripts: /tmp/claude-1000/-home-narolski-mambamorph/c2840dc9-dd37-4619-9347-d8a76080b93f/scratchpad/d.py and /tmp/claude-1000/-home-narolski-mambamorph/c2840dc9-dd37-4619-9347-d8a76080b93f/scratchpad/e.py.

## 2. Findings

**F1 (major): FM(H,H) is H minus 1 grey level, so this is not "matched rendering".**
- Why: in `/home/narolski/mambamorph-code/scripts/96_facemorpher_tool.py:34-42` (sha 954e9c02, verified), the tool(H,H) case uses the same points for source and target. The warp is therefore the identity, and `weighted_average(H,H)` returns H. The only change is uint8 truncation in `warper.py:56`.
- Measured: FM(H,H) − H is always −1, never larger. It touches 8.5% to 19.3% of pixels (median 14.0%). Image size (512×512×3 uint8), PNG and black-border fraction are identical.
- FM(H,B) is different: real bilinear resampling at sub-pixel positions inside the hull, and a 50/50 average of two photos over the whole frame.
- A one-line statistic (mean |horizontal pixel difference|, lower means morph) already gives these AUCs:

| Contrast | AUC of the one-line statistic | AUC of file size |
|---|---|---|
| FM(H,B) vs FM(H,H) | 0.736 | 0.637 |
| FM(H,H) vs H | 0.515 | 0.520 |

- So read 1 still mixes up "blend" with "smoothing / averaged noise", and read 2 is close to a null control.
- Fix: relabel everything; keep the batch as a cheap descriptive read. Replacement text:
  - prereg §2(d): "FM(H,H) is not a rendering control: with identical point sets the tool's warp is the identity, and FM(H,H) differs from H only by −1 grey level on 8–19% of pixels (reviewer measurement). FM(H,B) carries sub-pixel bilinear resampling inside the hull and a 50/50 average of two photos over the whole frame. Read 1 is therefore not matched for resampling history."
  - Read 2 is renamed "1-LSB truncation control", with the labels "no truncation reaction / truncation reaction".
  - §5 "present" licence becomes: "Sb ranks FaceMorpher two-person morphs of random-identity FFHQ pairs above near-identical copies of the host photo better than B (or A); the contrast is not controlled for resampling or averaging."
  - Delete "at matched rendering" everywhere, including the xf1_read.py docstring.
- A truly matched negative would be a warp-only H toward the (H,B) mean shape, without blending. That is a new image build, so it needs a DATA request and the author's word (same status as D13).

**F2 (major): the averaged background adds a border cue to the morph class only.**
- 77.9% of pairs have more than 1% of pixels where exactly one of H or B is black border (median 2.0%, p90 7.0%). Those pixels come out as half-intensity bands in FM(H,B).
- Fix (CPU only, no image operation): compute `excl_border = mean((H==0).all(2) ^ (B==0).all(2))` per pair. Print read 1 per arm within terciles of that value, and within terciles of the eye-distance gap |ied_host − ied_partner| from D12a `pairs.csv`. Both are descriptive, registered now.

**F3 (major): the 12-component bootstrap is wrong in kind and too coarse.**
- The pairing is a permutation, so its components are cycles. Dependence links only neighbours on a cycle: host h shares a face with partner p(h).
- Resampling 12 cycles, one of them 105 hosts, gives near-degenerate intervals.
- Fix: decide with a cycle-block bootstrap; also print a leave-one-component-out range and a host bootstrap as sensitivities. Blocks are consecutive runs of 5 along each cycle, giving 64 blocks. Code for xf1_read.py, replacing the `members`/`draws` construction:
```python
nxt = {r["host"]: r["partner"] for r in rows if r["klass"] == "FMHB"}; BL = 5
blocks, seen = [], set()
for h0 in hosts:
    if h0 in seen: continue
    cyc, x = [], h0
    while x not in seen: cyc.append(x); seen.add(x); x = nxt[x]
    blocks += [cyc[i:i + BL] for i in range(0, len(cyc), BL)]
draws = [np.concatenate([blocks[i] for i in rng.integers(0, len(blocks), len(blocks))]) for _ in range(B)]
# sensitivities: loco = [stat(n,...,[h for h in hosts if comp[h] != k]) for k in ug]; host bootstrap rng.choice(hosts, 299)
```
- Smallest detectable gain: by Hanley–McNeil, SE(AUC) is about 0.022 at AUC 0.65 with 299/299. Image-sampling error is shared across seeds, so averaging 5 seeds does not shrink it.
  - "Lower bound above 0" needs an observed gain of about 0.045 or more.
  - 80% power needs a true gain of about 0.06–0.07.
  - "Absent" needs an observed gain of about −0.015 or less.
- Your own predicted gains, −0.02 to +0.04, almost guarantee "inconclusive". State this in §6.

**F4 (major): the pairs are random-identity pairs, easier than real attacks.**
- Existing glintr100 embeddings (`/mnt/t7/smad_next/MS1/ffhq/emb_kept.npz`, 900 keys, no new model output) give H–B cosine of median 0.00, range −0.15 to 0.29.
- MS1 kept frames below 0.40 similarity by construction, so similar pairs cannot exist.
- Fix: print the cosine distribution. Optionally print read 1 within cosine terciles, labelled "all pairs dissimilar". Add to the limitations: "random-identity pairs (FR cosine ≤ 0.29), about half likely cross-sex; not representative of attacker-chosen pairs."
