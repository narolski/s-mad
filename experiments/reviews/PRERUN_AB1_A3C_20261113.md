### Findings

**1. Major: the balance gate is circular and passes by construction.**
- Where: `src/AB1/ab1_hbw_read.py:92,95`; prereg.md:442-444.
- The problem: the gate is the weighted AUC of round-0 `surround_logreg`. That is the very covariate the propensity model was fitted on (`src/adversary/ipw.py:83-86`).
- Simulation: one covariate at AUC 0.79, n = 1,000/2,000, the same logistic model and 1/99 clip. The covariate's weighted AUC comes out at 0.503 (200 replicates). It cannot fail.
- `surround_gbt` is only partly independent.
- The adversary already computes the non-circular check: surround, file and face floors refit with the weights on held-out folds (`ipw.py:99-103`, field `usable`). This is the same "refit" logic as the 1:1 build rule.
- If the reader keeps its own gate, the two "usable" decisions can disagree, which opens a cherry-pick.
- Replacement text for prereg.md:442-444: "Usable only if `floors/lcomb_ipw_build.json` (committed, pinned) has usable = true, i.e. ESS ≥ 300 per class and the refit weighted surround floor ≤ 0.60 for logreg and gbt. The reader recomputes ESS from the weights file, asserts it matches the build file to 1e-6, and prints (not binding) the weighted AUC of the round-0 held-out surround scores and the refit weighted file floor."
- Code change at line 95: `gate["ok"] = bool(build["usable"] and abs(build["ess_morph"]-ess(wp))<1e-6 and abs(build["ess_genuine"]-ess(wn))<1e-6)`.

**2. Major: the reader does not check the build report, the generator pin or the labels.**
- Where: lines 82-86.
- Add these assertions:
  - `committed(BUILD_JSON, build_sha)`
  - `committed("src/adversary/ipw.py", "5d15fa611e00ec0f026a6d4d3ece869b46de1e8d94ffa48faa38f0e96a8bbcdc")`. That is the current sha at 104ee36, which matches prereg 334. Pinning it is what proves the weights used only the surround score and pre_ied, with no network score.
  - `all(int(r["label"]) == (r["id"] in set(pos)) for r in rows)`. The label column is currently ignored.
- Add the build sha to the command-line arguments and to `pins.sha256`.

**3. Major: the face guard is a different statistic from 3b's.**
- Where: line 93.
- 3b used the adversary's refit face floor. 3c re-weights the unweighted round-0 face scores.
- Replacement: "Guard: the build file's refit weighted_face_floor, max(logreg, gbt), below 0.80 …; the round-0 weighted face AUC is printed."

**4. Minor: rows with extreme weights are not reported.**
- Positivity: the morph weight is (1/3)/p and the genuine weight is (2/3)/(1−p).
- The thin-overlap rows are genuine photos with high p (they look like morphs) and morphs with low p. These get capped by the 1/99 percentile clip, not dropped. The clip leaves some imbalance, which finding 1's refit floor will catch.
- Add to "Printed", per class: the number of clipped rows, the maximum weight, the share of total weight carried by the top 1% and top 5% of rows, and the propensity range of each class against the other.

**5. Minor: state the estimand.**
- Stabilised weights on both classes target the pooled covariate distribution (1/3 morph, 2/3 genuine). The weighted AUC then estimates the AUC when both classes share that distribution of round-0 surround score and pre_ied. That is valid, but it means "balanced on the adversary's surround score and eye distance", not "balanced on history".
- Weighting both classes is correct for this target.
- Overlap weights would raise the ESS. Adding them now would create a second route, so leave them out.
- Add to the licence text: "balanced on the round-0 surround score and pre-alignment eye distance".

**6. Ok: the ESS floor of 300.**
- Simulated SD of the paired weighted gain: 0.012 at a morph ESS of about 490 (simulated genuine ESS about 1,600). The SD of g_w − g_full is 0.008. Scaled by √(490/300), that is about 0.015 at ESS 300.
- The gap between "half" and the 0.10 bar is 0.04 at g_full = 0.12, which is about 2.7 SD. The floor is adequate.
- Two caveats:
  - All seeds share one set of rows, so this noise is common to every seed vote. The seed-mean interval and the null are the honest summary.
  - At g_full ≥ 0.20 the two cut-offs meet, so the per-seed call can sit right on the boundary.

**7. Ok, with a wording change: the permutation null.**
- Re-assigning weights within class keeps the weight distribution and the ESS and breaks the link to surround score. So it answers "shrinkage beyond what an arbitrary reweighting of the same concentration produces".
- Add: "the null is one-sided (percentile of g_w, low = more shrinkage) and conditional on the rows."

**8. Ok: the reader mechanics.**
- Weighted AUC with ties (searchsorted left/right over cumulative weights) is correct.
- The paired bootstrap uses the same draws for every arm.
- Missing seeds: a seed counts only if A, B and Sb are all present, the same as `ab1_read.py:270`.
- Minor: a missing A run would also drop the primary Sb − B read. Either state this or count Sb − B seeds separately.

**9. Major: block cherry-picking between the 3b and 3c routes.**
- Add: "Order: (a) `ab1_hb_read.py` once on the committed lcomb_bal, labelled descriptive, not read; (b) `ab1_hbw_read.py` once. 3c is the only verdict-bearing history read. Both outputs are reported. If 3c is not read, no further weighting, trimming, overlap or matching route is added for H-hb1, and the 3b licence text for 'not read' applies. The weights are not re-tuned (ADV prereg 341)."
- What each outcome licenses: as in 3b, with finding 5's qualifier. Development data, post hoc, never held-out or test evidence.
