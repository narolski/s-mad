**Verdict: GO WITH FIXES.** It costs no GPU and reads only the development test-host scores. The code derives the 32 linked hosts correctly. But the registered mechanism is wrong, the "matters" rule fires on noise often enough to be a coin flip, and the read misses the most likely sign of the effect. Fix items 1 to 4 before running, as a text-and-code amendment to ac7a1ec (5a). Nothing has been computed yet, so this is still allowed.

## Findings

**1. Major: the evaluation hull is not the training hull, so there is no "same geometry" near-duplicate.**
- I checked with the builder code (`src/AR1/splice.py:26-41`, `:150`), `AR1/pool.csv` and `ladder_split.csv`, reading counts only.
- Training host T's S3/S0 hull is built from T's photo H and partner X's photo S (B is the partner's own S photo on all 536 hosts).
- Test host X's own S4/S3/S0 hull is built from X's photo H and X's own partner P's photo S.
- X's partner is never T: 0 of 32 pairs match. The pool has no test-to-train partner edges. The 32 X's partners are 21 development hosts, 10 test hosts and 1 excluded host.
- The H and S photos differ for all 32 hosts.
- So the shared part is about half an outline: X's S-photo landmarks appear in a training hull. In X's own evaluation items they appear only inside the face, in the R3/R2w warp targets. The hull uses X's other photo plus a different person.
- The link is weak and partial. Any expected effect is small.
- Replacement text for the amendment: "The evaluation hull of a linked test host is not the training hull of its partner (0 of 32 pairs equal). The training hull uses the test person's S-photo landmarks for half its points. The test person's own evaluation hull uses its H photo and a different partner. The link is partial landmark shape, not a duplicated item."

**2. Major: the read misses the likely sign of the effect.**
- If the network learned "this outline means genuine", the effect would lower the logits of X's S4, S3 and S0 together, because all three share one hull (7b).
- That means fewer S3/S0 flags and more S4 misses. The S4-vs-S3 AUC can stay flat while both rungs shift.
- `shape_link_read.py:78-80` computes no S4 miss rate and no logit location. The S0 flag rate is uninformative because it is at the floor (0-1 of 191, `result.md:18`).
- The AUC test is one-sided upward (`:118`, `da >= 0.05`).
- Fix:
  - Add `miss_S4 = (s4 <= 0).mean()` and the median logit per rung (S4, S3, S0).
  - Make the primary statistic the linked-minus-clean difference in each host's mean logit over S3, S0 and S4.
  - Make the AUC test two-sided.
  - Keep R4 vs R3 and the R3/R4 flags, labelled as the low-link control (no hull involved).

**3. Major: the "matters" rule fires on noise about 25-40% of the time.**
- At AUC ≈ 0.73 (`result.md:21`), the Hanley-McNeil standard error is about 0.063 for 32 vs 32 hosts and about 0.028 for 159.
- The standard error of the difference is about 0.069, so the smallest difference detectable at 80% power is about 0.19.
- For the S3 flag rate (≈ 0.35), the standard error of the difference is about 0.092, so the smallest detectable difference is about 26 points.
- The 0.05 and 10-point thresholds sit below one standard error. Under no effect, each seed crosses one of them with probability about 0.4.
- The five seeds share the same 191 hosts, so they are strongly correlated. "≥ 4 of 5 seeds" therefore gives little protection.
- Fix: same splits for all seeds, averaged.
  - Store each draw of the null (the code already reuses rng 20261202, so the splits are identical across seeds).
  - Average the statistic over the 5 seeds per draw.
  - Decide on the 5-seed mean against that joint null.

**4. Major: the wording "no visible effect" overstates what n = 32 can show.**
- Replacement text: "No effect detectable at n = 32 (smallest detectable difference about 0.19 AUC, about 26 flag points, and [computed] logits)."
- Have the code print the detectable size from the null's spread.

**5. Minor: the linked hosts differ somewhat from the clean ones.**
- FRGC share: 28 of 32 linked vs 126 of 159 clean.
- Partner is a development host: 21 of 32 vs 78 of 159.
- Only 11 of the 32 are in the 80 hosts clean of development.
- Partner similarity (cos_HB median 0.225 vs 0.233), same-person similarity (cos_HS 0.863 vs 0.869) and R_neutral are balanced.
- Fix: draw the null with the same make-up as the 32 (by database and by whether the partner is a development host), and print these covariates. Add a "linked vs clean within clean-of-development" print, labelled n = 11.

## Replacement rule (FS1 decides)

- **"Shape link visible":** the 5-seed mean of the primary statistic (mean logit over S3, S0, S4) falls outside the 95% stratified joint null, and in the predicted direction (lower logit for linked hosts). Report the S3-flag, S4-miss and AUC differences beside it, each with its null interval.
- **"No effect detectable at n = 32":** the primary statistic and the S4-vs-S3 AUC difference are both inside the null. Always print the smallest detectable sizes.
- **Otherwise "inconclusive".**
- The AB1 seeds are printed only.

## What each outcome allows for the wording "on new persons"

- **Not detectable:** "new persons (appearance); for 32 of the 191, face shape entered training as half of a negative's outline. Excluding them changes [clean minus all]." Always report the 159-host value beside the 191-host value. Do not claim the effect is absent.
- **Visible:** headline the 159 clean hosts. For the 32, call the reads "new in appearance, not in shape".
- **Inconclusive:** same as visible. Report the 159 hosts as the primary result.

The 80 hosts clean of development remain a separate caveat whatever the outcome.
