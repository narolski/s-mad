## Verdict: GO WITH FIXES (F1 blocker; F2-F5 major; all CPU or text, no GPU)

- **F1 (blocker).** AB1's A and Sb can end up on another platform, and then AB1 reads nothing: SE1's prereg lets SE1
  move to Athena or rented machines (10:30 trigger live; SE1 smoke forecast 12:50); `ab1_read.py` `tar_for` returns the
  SE1 tar whenever it exists, `load()` rejects a non-H100 one, and never falls back to AB1_A / AB1_Sb. Fix: register
  that AB1's A and Sb are the WCSS H100 networks; if SE1 is not on WCSS H100, AB1 fits A and Sb itself (10 tasks, about
  12 H100-h) and never reads SE1's; `tar_for` takes the SE1 tar only if `load()` accepts it; SE1 to confirm it will not
  move platform without telling AB1.
- **F2 (major).** SbH is confounded with the stored-small copies: af0_half61 is 200 of the 225 unique FRGC stored
  negatives in Sb; SbH keeps 25 (frgc|s61 25 photo61 against 200 u5061; one image repeated up to 16 times). Any SbH rise
  on softened photos or C2P can come from storage. The Δsoft read is the stored-small operation on development persons,
  so H-ab3s restates H-ab1 (near-circular for SbS). Fix: rebuild SbH dropping only af0_half and lad_half (keep
  af0_half61; SbS removes it), making the removed sets disjoint; call Δsoft "development storage rise"; H-ab3 falsified
  only as "not needed given the stored copies". Optional SbHS arm (about 6 H100-h).
- **F3 (major).** Reader verdicts wrong with missing seeds: in `c2p_verdict` a missing X counts as not passed, so with
  1-2 X tars R1 prints "not replicated" instead of "not read (too few seeds)"; same for H-ab1s, SbS C2P, SbL guard and the
  H-ab1 ratio rule. Fix: count X's read seeds within A's control seeds; ≤ 3 → "not read"; add a mock with two Sb seeds
  missing; the mock has no storage shift and never produces "passes"/"fails"; add a shift as c2p_read's mock does.
- **F4 (major).** Falsification probably out of reach for mid-rate reads: seed noise dominates (SE1 review about 0.04
  AUC between arms in same-seed differences); with a true zero effect "rise ≤ +0.01 on 4 of 5" happens only about 20-30%
  of the time for reads near 0.35 (S3). Fix: a seed-mean rule with an interval as the decider (or a registered
  secondary) for H-ab2, H-ab3 and the attribution table; state which decides.
- **F5 (major).** Timing and the single read: WCSS priority 681 against about 10,700 for top users; 17:30 needs about 20
  H100s from about 13:00; §7 registers one read when all have ended or 14 Nov 12:00, so a 17:30 partial read would break
  it. Decide now whether to register a 17:30 read time; consider letting one smoke gate both fit arrays (lead); keep the
  seed-by-seed order.
- **F6 (minor).** Volume matching does not match volume: with fixed steps, passes per unique image differ from Sb by
  1.19 (SbZ), 1.60 (SbH), 1.22 (SbS). Say so.
- **F7 (minor).** The reader does not check provenance: assert task_info steps (6,250 / 12,500), limit 0, pack 96c31ae2,
  overlay (AB1) or de26d6ce (SE1); train.csv sha256 per arm from train.log; finite loss (SE1's regex).
- **F8 (minor).** Fit jobs trust run.sh.sha256 beside the script; hard-code the pin as SE1 does.
- **F9 (minor).** Closed-set assertion covers evaluation rows only; training rows are FS1 subsets (safe by construction);
  add the assertion or reword.
