# Version 3 selection reader implementation and admission

`src/NEXT/read_selection.py` is a reviewable implementation of the approved rule's numerical decision logic and an initial native adapter for the resolution-study fit/refit outputs. **It has not been used on production scores and is not yet approved for a scientific read.** No admission manifest is supplied with invented eligibility or missing-arm dispositions.

## Implemented behavior

- Inclusive, unrounded criteria (a)–(f), five-seed denominators and explicit failed/missing-seed records. Four valid read seeds must all meet a four-of-five count; three or fewer yield "not read".
- The same four seeds must meet the storage-rise bound at both sizes. Plain-control and morph-evasion counts retain their own registration's per-size rules. Each of the two kernel quantities has its own four-of-five count, as section 5(e) explicitly states.
- Full-landmark, within-D ladder and surround-matched contrasts use the pinned exact rows. Within-D quintiles are recomputed on each drawn row set, including the point estimate, with ten positives and ten negatives per accepted stratum and n_pos × n_neg weighting. The bootstrap resamples the pinned person-component column, with shared `default_rng(20261115)` row draws across seeds, networks and floors. The seed-mean ladder interval averages per-seed statistics, never logits.
- All four in-distribution floor families and both per-row same-data transfer learners are printed beside each candidate/comparator deciding contrast, with network-minus-floor intervals from the same draws. The prior standalone floor confidence intervals are not substituted. Floor vectors/bootstrap values are cached without changing the draws.
- Printed descriptive reads cover development-only and clean-test-only ladder hosts, exclusion of shape-linked hosts, the same-host FaceMorpher contrast, and lcomb_bal labelled "do not cite as a test".
- Storage rises, registered plain-control bars and morph-evasion falsification; seven-family TT1 mean; MEDS person-bootstrap upper bounds with seed 20261125; same-person splice and exact development-border flags; training/held-out kernel sensitivity; and native provenance/registration guards.
- Fixed challenger order; no largest-gain tiebreaker, ensemble, seed selection or benchmark-driven choice. Resize-mixing output names the transfer learner's limited scope: stored frames of the same list.
- Separate selection and confirmation stages, fixed once-journal locations, and a pure seeds-by-components bootstrap helper for the future DINOv3 adapter.

## Current native format coverage

The initial supported production adapters are `rz1_fit` and `rz1_refit`, matching the reviewed static formats in `rz1_read.py`, `rz1_score.py` and `rz1_rescore.py`. They read only required named members into memory, never extract files or load weights, reject duplicate members, and use `np.load(..., allow_pickle=False)`.

Fit checks include the exact task arm/seed, H100 GPU, input/overlay hashes, 6,250 steps, resolution/batch/accumulation, item count, pre/post guards, finite loss, training/evaluation/TT1/MEDS/cross manifest hashes, primary transforms, complete ID order, unique training-path order/labels/kinds and finite arrays. The refit adapter also requires the source archive identity/hash, H100 full-manifest bit-identity gate, scorer and input pins, unrestricted scoring and the registered original AB1 Sb source pins.

Initial native coverage can support SbMR, SbM and Sb512 after admission and all guards. Sbc additionally requires the pinned author crop-scope ruling. SbMR512 is explicitly refused until its kernel-test registration and complete adapter exist. SbFM, GX and DINOv3 native adapters are not implemented here. If any such arm is otherwise eligible, **the whole scientific invocation is refused before any candidate member is opened**. An implementation gap cannot be labelled infrastructure failure or used to default to Sb.

The fresh-seed decision stage is distinct, but the initial native refit adapter pins only the original 408–412 source networks. It deliberately refuses fresh 413–417 AB1 source pins until the confirmation registration and corresponding reviewed adapter extension exist. This preserves the future confirmation requirement rather than pretending that its inputs already exist.

## Required admission manifest

The lead must prepare and independently review a committed `next-admission-v1` JSON file. It contains:

- `stage`: `selection` or `confirmation`; `approved: true`; `batch_closed: true`; exact `numpy_version`; `rule_sha256`.
- `pinfiles`: relative paths to the committed common package, support package and a final admission/code/receipt pin file. These must collectively pin the rule, this reader, admission JSON, exact independent review, support JSON, all source manifests, all contrast and transfer files, and opaque arrival/hash receipts.
- `support`: `experiments/NEXT_method-selection-rule/inputs/support/support_v3.json`. `validate_support` resolves its private MEDS row indices in memory and reconstructs expected score-row order from its pinned source manifests. MEDS identifiers are never serialized into result files.
- `review`: a committed independent admission review containing the exact line `NEXT_ADMISSION_GO <sha256-of-admission-json>`. This avoids a self-referential hash: the admission names its review file; the review binds the final admission bytes; the final pin file binds both.
- `receipt_manifest`: a committed JSON object keyed by network key. Each entry has `archive`, `sha256`, `hash_verified: true` and timezone-aware `verified_at`. Selection archives must have arrived and been hash-verified by 15 November 2026 at 18:00 CET.
- `input_files`: mappings `lcomb`, `ladder`, `matched`, `lcomb_bal`, `ladder_dev`, `ladder_test`, `ladder_no_shape`, `facemorpher` to the exact package CSVs. `transfer_files` maps `Sb` to `floors/transfer_Sb_rows.csv`; its per-set row IDs, labels and component IDs must agree exactly.
- `floor_columns`: for each of `lcomb`, `ladder`, `matched`, four mappings named `all_cue`, `non_F27_non_BLEND`, `surround`, `face_box` to the previously fixed floor prediction columns. Independent review must verify these against the committed floor definitions. Choosing a column based on candidate outcomes is prohibited.
- `arms`: every name in the fixed eight-arm list has an explicit disposition. A read arm names fixed seeds, candidate/comparator/control/yardstick network keys for each seed (or null for a registered missing seed), `pre_binding_scientific_open: false`, and a pinned `eligibility_review`. Sbc also names `crop_scope_ruling`. Network roles and seeds are checked against the rule, including Sb0 as the RZ1 comparator, A0 or A512 as plain control, and the original same-seed AB1 Sb exact-gated yardstick.
- A `not_read` arm requires a pinned authoritative reason: deadline, infrastructure failure, missing seeds, a failed registered gate or missing required inputs. A pre-binding scientific opening is an ablation unless the author's exception has been resolved in the admission before use. Unsupported code is never an allowed reason. Confirmation may mark other arms `not_selected`, with evidence of the prior fixed-rule choice.
- `networks`: each used key has `archive`, `sha256`, `format`, `prefix`, `arm`, integer `seed`; refit records also specify `source_network: {name, sha256}`. Full source identity is checked, not just a filename or matching first eight hash characters.
- `once_journal`: exactly `/mnt/t7/smad_next/NEXT/selection_rule_v3_once` or `/mnt/t7/smad_next/NEXT/confirmation_rule_v3_once`. Confirmation also requires a pinned `selection_record`, fixed `selected_arm` and `confirmation_registration`.

The admission must justify that the registered batch is closed, not merely set a boolean while eligible fits remain pending. The independent review must verify the exact eligibility dispositions, provenance and recorded timing before supplying its GO line. A candidate that remains pending or has an unsupported adapter is an execution blocker, not a scientific loss.

## Production invocation after review

Use a clean detached checkout containing the binding commit and final pins; preserve unrelated working changes elsewhere. The output parent must already exist on durable storage. The Python environment must match the admitted numpy version.

```bash
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 NUMEXPR_NUM_THREADS=2 nice -n 10 \
  /home/narolski/mambamorph-code/.venv-spark/bin/python -I src/NEXT/read_selection.py \
  --admission experiments/NEXT_method-selection-rule/ADMISSION.json --preflight
```

Preflight checks committed bytes, exact hashes, metadata, archive binary hashes and all shared rows/floors without reading candidate members or consuming the scientific once marker. Omit `--preflight` only after independent release. The atomic journal claim precedes the first candidate-member read. A failed read writes `FAILED.json` and keeps the journal, preventing silent replay with changed inputs. Successful output is aggregate per-seed `result.json` plus a completion hash.

## Synthetic verification and remaining review

Tests in `src/NEXT/tests/mock_selection.py` use only generated temporary metadata, arrays and tar files. They cover tied AUC, exact margins, fixed order, missing/failed seed counts, joint storage versus separate kernel counts, within-D component resampling, the unpaired helper, once-journal refusal, pin tampering, unsupported eligible arms, wrong role/seed/source mappings, native fit/refit schemas, non-finite values, wrong primary/MEDS hashes and ID order. No production reader or arm reader was invoked.

Before release, the independent reviewer must additionally inspect the entire registered-rule mapping, confirm floor-column choices and descriptive-read scope, review complete admission/receipts, and validate any newly supported raw formats. The native adapter tests do not establish real archive validity. The numeric helper for DINOv3 is not a complete DINOv3 production adapter. No selection or benchmark conclusion has been drawn.
